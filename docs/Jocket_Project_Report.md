# Jocket 项目完整开发报告

生成日期：2026-05-25  
当前主版本：2.0  
项目定位：A 股智能行情、个股研究、市场情绪复盘与 AI 投研辅助工具。

## 1. 项目概览

Jocket 是一个面向 A 股研究辅助的 Streamlit 应用，最初从本地个股评分工具演进为包含数据源路由、基本面估值、市场情绪、AI 行情问答、TradingAgents 投研流程和云端部署能力的一体化研究工作台。

项目最终收敛为四个核心入口：

- AI 洞察：以自然语言方式调用项目内行情、新闻、情绪、预测和研究框架。
- 个股行情：围绕单只股票输出价格、技术评分、基本面估值、新闻和高价值信号卡片。
- 市场情绪：复盘涨停生态、炸板率、情绪周期、板块梯队和市场主线验证。
- 投研分析：接入 TradingAgents 风格的多角色研究、辩论、风控和报告生成流程。

## 2. 版本与分支整理

本轮清理目标是只保留 `1.0` 与 `2.0` 两个分支，并以当前 `2.0` 作为最新版本。

版本脉络如下：

- `1.0`：完成 Jocket 项目化、GitHub/Railway 部署配置、基础 Streamlit 应用和个股分析功能。
- `2.0`：加入 AI 行情、市场情绪、a-stock-data 信号层、TradingAgents、UI 一致性优化和性能修复，是当前最新主线。

已清理的项目残留包括：

- 临时 DOM 抓取脚本、单票调试脚本和输出文本。
- 本地补丁文件、scratch 测试文件和 Codex 调试截图。
- 非运行必需的 vendored 参考包 `a-share-stock-picker-master`。
- `.gitignore` 增加了调试产物规则，防止后续再次进入版本库。

## 3. 功能实现总览

### 3.1 个股行情与评分

个股分析页围绕“价格结构 + 技术评分 + 基本面估值 + 外部事件信号”构建：

- 支持股票代码和中文名称模糊搜索，减少用户记代码的成本。
- 支持多数据源自动路由，包括 a-stock-data 直连思路、百度股市通、AkShare、efinance、同花顺和 Yahoo Finance。
- 输出短线评分、中长线评分和综合评分。
- 展示 K 线、均线、成交量、RSI、MACD、KDJ、评分拆解和风险提示。
- 基本面模块覆盖公司画像、PE/PB/PS、ROE/ROA、D/E、股息率、简化 DCF、财务表和 Ratings Snapshot。

设计原则是“评分只是研究排序，不直接给买卖指令”。页面更多使用“重点研究、优先观察、谨慎观察、等待验证、暂不优先、数据不足”等研究语言。

### 3.2 a-stock-data 信号卡片

项目将外部公开数据源抽象成信号卡片，而不是把原始表格直接堆到页面：

- 估值压力：PE/PB/ROE/股息等综合判断估值是否容易解释。
- 预期兑现难度：机构 EPS、一致预期、Forward PE 和研报样本量。
- 资金流验证：20 日主力净流入、正流入天数占比和资金承接强弱。
- 龙虎榜强度：机构席位、净买入和游资行为。
- 解禁压力：短期解禁规模和时间压力。
- 融资情绪：融资融券变化判断杠杆资金态度。
- 大宗交易折溢价：观察大额成交对市场定价的影响。
- 公告事件强度：将公告、新闻和事件转为可读结论。
- 热点归因匹配：判断个股是否真正处在市场主线上。

这些卡片遵循“有评价、有阈值、有决策含义”的原则，只把影响判断的指标放到前台。

### 3.3 市场情绪

市场情绪页从单纯看涨跌家数，升级为市场生态复盘：

- 涨停池、炸板池、跌停池、强势股池。
- 情绪指数、涨停强度、炸板率和冰点压力。
- 板块情绪热力图和三维情绪趋势。
- 次日条件观察池。
- 主线与资金验证：结合同花顺热点、龙虎榜、行业轮动、北向资金和指数/ETF 风险偏好。
- 支持交易日、观察窗口和缓存刷新，减少重复拉取公共源。

这部分的设计目标是回答“市场有没有赚钱效应、主线是否被资金确认、次日该观察什么”，而不只是罗列行情。

### 3.4 AI 行情

AI 行情是项目的自然语言入口，核心能力包括：

- Gemini 与 DeepSeek 双模型配置。
- 自动加载 `.env` 或 Streamlit secrets 中的 API key。
- 通过 Skill 路由选择 alphaear-stock、alphaear-news、alphaear-deepear-lite、a-stock-data、alphaear-search、alphaear-sentiment、alphaear-predictor、alphaear-signal-tracker 等上下文。
- 把项目内新闻、市场情绪、个股信号卡片和外部技能结果汇总成模型上下文。
- 针对缺失数据主动询问是否调用对应技能，避免模型凭旧知识编造价格或财务数值。
- 支持手动选择技能按钮，让用户决定本轮问题更偏行情、新闻、情绪、预测或报告。

AI 的系统约束明确要求只使用当前上下文，不使用模型记忆中的旧股价和旧财务数据。这是 Jocket AI 模块最重要的安全设计之一。

### 3.5 TradingAgents 投研流程

投研分析页接入了多角色研究框架：

- 市场分析师、基本面分析师、新闻分析师、社媒分析师。
- 政策分析、热钱跟踪、解禁观察等 A 股增强角色。
- 多方/空方研究员辩论。
- 激进、保守、中性风控视角。
- 研究经理和组合经理生成最终结论。
- 支持历史报告、删除确认、PDF 下载和进度面板。

这使 Jocket 不只是一个行情面板，还能输出结构化投研过程。

## 4. Debug 与问题修复复盘

### 4.1 数据源与行情稳定性

开发中主要遇到的数据问题：

- AkShare/东方财富接口在部分 macOS、Python、代理环境下会出现 SSL 或 ProxyError。
- efinance 实时行情和历史行情偶发不可用。
- 短窗口例如 14 日会导致历史数据不足，页面空白或评分异常。
- 公共直连接口偶尔 404、超时或字段结构变化。

对应修复：

- 建立 provider router：优先直连可用源，失败后按 efinance、AkShare、yfinance 等顺序回退。
- 增加百度股市通和 Sina HQ 作为行情兜底。
- 将评分所需历史长度与用户展示窗口解耦，短窗口页面仍可用更长历史计算技术指标。
- 对公共接口做异常保护和 warning 收集，局部失败不阻断主页面。
- 对实时价保持更严格语义：能取得实时行情时替换当天日线，取不到时提示限制，不静默伪装成实时数据。

### 4.2 Streamlit 与云端兼容

部署和 UI 中的主要问题：

- Streamlit Cloud 缺少 `markdown` 依赖导致页面失败。
- Streamlit 组件自动生成的 key 重复，引发 `StreamlitDuplicateElementId`。
- 移动端导航横向滚动和按钮布局异常。
- AI 行情页和其他页面的导航、命令栏位置不一致。
- 部署环境中部分 CSS 选择器、动画和组件结构表现与本地不完全一致。

对应修复：

- 补齐 requirements 并固定关键依赖版本。
- 为 Plotly 图表和动态按钮增加唯一 key。
- 通过 CSS 和少量前端增强脚本统一导航宽度、选中态、移动端单行布局。
- 把 AI 行情 prompt 收进和其他页面一致的 command bar。
- 增加纯 CSS fallback，保证 Streamlit Cloud 中 Q&A 卡片、横向导航、技能按钮、历史报告按钮和 loading 动画一致。

### 4.3 UI 动效与视觉问题

重点修复事项：

- 卡片 hover glow 与鼠标位置错位。
- “来财来财”按钮 glow 被外层容器裁切。
- 按钮高亮动效恢复后又出现边界溢出。
- 市场情绪日期显示不一致。
- 历史报告删除按钮和弹窗关闭反馈慢。

对应修复：

- 使用卡片内 pointer 坐标更新 CSS 变量，让 glow 跟随真实鼠标位置。
- 为按钮 glow 使用严格贴合按钮边界的伪元素和 overflow 控制。
- 增加运行中状态样式，避免用户误以为点击无响应。
- 统一日期格式与缓存 key。
- 对历史按钮、删除按钮和取消按钮增加前端样式与交互补丁。

### 4.4 AI 响应与上下文性能

AI 模块曾出现的问题：

- AI 洞察上下文加载慢。
- 模型可能引用旧知识中的过时股价。
- 股票查询默认值和控件状态容易让用户误操作。
- 技能路由不明确时，问题上下文不足。

对应修复：

- 跳过慢速基本面刷新，优先使用价格、量价、技术评分和 a-stock-data 信号卡片。
- 系统提示中强制禁止使用预训练股价、财务数值和旧行情记忆。
- 将用户短回复与最近历史问题合并，识别“允许/可以/继续查”等补数据意图。
- 增加技能选择按钮和可用技能目录。
- 统一搜索框和默认控件，不再依赖硬编码默认股票。

## 5. 设计思路

### 5.1 产品设计

Jocket 的核心设计不是“展示更多数据”，而是把分散数据转成研究判断：

- 原始数据作为证据层保留。
- 评分和卡片作为判断层前置。
- AI 作为解释和串联层。
- TradingAgents 作为结构化投研流程层。

这个结构让用户可以从三个层级使用产品：

- 快速看结论：分数、评级、风险、信号卡片。
- 复盘证据：K 线、指标、资金、新闻、公告、龙虎榜。
- 深入推理：AI 问答和多角色投研报告。

### 5.2 功能设计

功能设计遵循几条原则：

- 数据源可回退：公共金融数据源不稳定，所以任何单源失败都不应让页面整体崩溃。
- 结论可解释：每个评分和信号卡片都要有阈值、来源和决策含义。
- 用户可控制：AI 技能和日期窗口等关键参数尽量显式给用户。
- 缺失要披露：无法取得的数据不编造，以 N/A、warning 或“数据不足”表达。
- 投资语言克制：不输出无条件买入卖出，只输出研究观察、验证条件和风险。

### 5.3 UI 设计

视觉上采用暗色金融仪表盘与 Bento Design：

- 顶部 hero 承载当前页面语义和关键状态。
- 卡片网格展示最重要指标。
- 图表使用高对比线条和 glow 视觉，提升行情趋势识别。
- command bar 统一承载输入、日期、窗口、模型和执行按钮。
- 导航入口收敛，避免页面过多造成选择成本。
- 移动端保持单行导航和可滚动内容，尽量不牺牲核心操作。

交互亮点包括：

- “来财来财”作为统一执行按钮，形成品牌化操作记忆。
- Bento 卡片 cursor glow 跟随鼠标，强化探索感。
- AI 技能按钮可手动切换，让复杂模型上下文变得可见。
- 市场情绪窗口按钮统一成分段控件，减少日期和窗口选择摩擦。
- TradingAgents 历史记录以紧凑 pill 形式展示，支持快速回看和删除。

## 6. 项目亮点与特色

- 多源行情容错：适配国内公共源不稳定的现实环境，自动回退并保留诊断信息。
- 信号卡片化：把资金、估值、公告、龙虎榜、解禁、融资、热点等复杂数据压缩成可行动的判断卡片。
- AI 上下文安全：明确禁止模型用旧知识回答股价和财务，减少金融场景幻觉。
- 市场情绪闭环：从涨停生态到主线资金验证，再到次日观察池，适合盘后复盘。
- 研究过程产品化：TradingAgents 把分析师、研究员、风控、经理的流程放进 UI。
- 部署可用：包含 GitHub、Railway、Streamlit Cloud 相关配置和依赖修复经验。
- UI 记忆点强：暗色 Bento、glow 卡片、统一命令栏和品牌按钮使产品辨识度更高。

- 个股研究主链路可用。
- 市场情绪复盘链路可用。
- AI 行情问答链路可用，需要本地或云端配置 API key。
- TradingAgents 页面已接入，支持报告历史和 PDF 导出。

## 8. 后续建议

建议后续沿三条线继续推进：

- 数据质量：引入更稳定的正式数据源，补充财务、公告、行业资金和历史估值分位。
- 产品体验：把常用股票池、观察池、复盘模板和报告导出做成固定工作流。
- 模型评估：建立评分回测和 AI 回答质量检查，用真实复盘结果校准评分权重与阈值。

如果要对外展示项目，建议准备一个“演示用固定数据快照”，避免现场公共接口波动影响演示效果。
